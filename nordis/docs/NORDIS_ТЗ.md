# NORDIS — техническое задание

**Версия 1.0 · 8 ноября 2026 · Елена Дарс (Helen Dars)**

NORDIS — платформа единого управления бизнесом для собственников с оборотом от 5 млн ₸ в месяц (Казахстан). Платформа собирает данные клиента из его систем, каждый день считает прибыль и деньги, даёт голосового ассистента «Елена» и ИИ-сотрудников (продавец, РОП, таргетолог и др.).

Документ описывает четыре этапа: **пробная версия (10 дней) → Лайт → Бизнес → Премиум**. Каждый этап строится только после того, как предыдущий проверен на живом клиенте. Первый пилот — **Яна** (производство и продажа косметики, Алматы и Шымкент, Kaspi).

## 1. Принципы продукта

1. **Не отключаем системы клиента.** CRM, 1С, Excel, Kaspi работают как раньше. Мы забираем копию данных по ключу API (только чтение) или из файлов.
2. **Сначала данные, потом ИИ.** Елена и ИИ-сотрудники отвечают только на основе данных в хранилище. Нет данных — отвечают «нет данных», и говорят, каких именно.
3. **Каждая цифра проверяема.** У любого показателя есть источник и дата обновления. Елена называет источник, если её спросят.
4. **Что нельзя подключить напрямую — берём файлом.** Еженедельные выгрузки бухгалтера из 1С — нормальный рабочий режим, а не исключение.
5. **ИИ действует в рамках правил клиента.** Три уровня: решает сам / предлагает — человек подтверждает / только собственник.
6. **Каждый этап измеряется в деньгах.** Итог пробной версии — отчёт «было → стало» по калькулятору эффекта.

## 3. Модель данных

Все таблицы содержат `tenant_id` (клиент NORDIS) и защищены row-level security. Денежные суммы — в тенге, целые числа (тиыны не храним, если источник их не даёт). Даты — `Asia/Almaty` (UTC+5).

### 3.1. Служебные

| Таблица | Назначение |
|---|---|
| `tenants` | Клиент NORDIS: название, пакет, дата начала пробного периода, налоговый режим, ставки |

## 4. Показатели

Считаются каждый день к **07:30 по Алматы** за вчера, неделю, месяц с начала, прошлый месяц и тот же период прошлого года (если есть данные).

| Показатель | Формула | Минимальные данные |
|---|---|---|
| Выручка | сумма `orders` (без отменённых) или ОПиУ | заказы или ОПиУ |
| Себестоимость | Σ количество × себестоимость SKU; иначе доля из ОПиУ | товары или ОПиУ |
| Маржинальный доход | выручка − себестоимость − доставка − упаковка | — |
| Маркетинг, ДРР | Σ рекламных статей; ДРР = маркетинг / выручка | реклама |
| ФОТ | Σ payroll + налоги на работников | ФОТ |
| Операционная прибыль | маржинальный доход − маркетинг − постоянные | — |
| Налог | выручка × ставка (упрощёнка) + фиксированные; иначе по режиму клиента | ставки в `tenants` |
| Чистая прибыль | операционная − проценты − амортизация − налоги | — |
| Деньги на счетах | Σ `cash_balances` на дату | банк/Kaspi |
| Прогноз денег 14 дней | остаток + ожидаемые поступления − платежи по `payment_schedule` и регулярным расходам | договоры, расходы |
| Кассовый разрыв | первый день прогноза с остатком < 0 (или < порога клиента) | прогноз |
| Лиды, цена лида | Σ лидов; расход / лиды по каналу и креативу | реклама |
| Конверсия лид → покупка | покупки / лиды за период | CRM |
| Стоимость клиента | рекламный расход / новые покупатели | реклама + CRM |
| Время первого ответа | медиана и 90-й перцентиль, отдельно ночь (22:00–08:00) | диалоги |
| Заявки без ответа | лиды без ответа > 15 мин | диалоги |
| Средний чек | выручка / заказы по каналу | заказы |
| Запас товара в днях | остаток / средние продажи в день | склад + заказы |
| Расхождение рекламы | расход в ОПиУ/банке − расход по кабинетам | реклама + банк |

**Сверка.** При подключении клиента считаем чистую прибыль по месяцам и сверяем с его ОПиУ. Расхождение больше 1% по любому месяцу — блокер запуска, разбираем вручную.

## 5. ИИ: общие правила для Елены и всех ИИ-сотрудников

1. **Ответы только из инструментов.** Модель получает инструменты (tool use), которые читают показатели и таблицы клиента. Свободный SQL модели не даём — только заранее описанные запросы с параметрами.
2. **Нет данных — нет ответа.** Если инструмент вернул пусто, ассистент говорит «в NORDIS нет данных о …, их можно получить из …».
3. **Источник по запросу.** Каждый инструмент возвращает источник и время обновления.
4. **Правила решений** (`rules`) у каждого клиента свои. Уровни: `auto` — делает сам; `propose` — отправляет предложение владельцу или ответственному, выполняет после «да»; `owner_only` — только сообщает.
5. **Журнал.** Каждое действие — в `ai_actions` с правилом, входными данными и результатом.
6. **Персональные данные.** Перед отправкой в модель телефоны и e-mail конечных покупателей заменяем на внутренние ID, где это не мешает задаче. Окончательные требования — после консультации юриста (раздел 12).
7. **Языки.** Русский — обязательно; казахский — понимать во входящих сообщениях с пробной версии, отвечать по-казахски — с Лайта (после теста качества).
8. **Тон.** Деловой, коротко, цифры с единицами. Без эмодзи у Елены.

### 5.1. Инструменты Елены (стартовый набор)

`get_metric(name, period, breakdown?)` · `compare_periods(name, a, b)` · `list_alerts(status?)` · `list_tasks(owner?, due?)` · `find_orders(product?, customer?, date_range?)` · `get_stock(sku?)` · `get_payment_schedule(days)` · `get_cash_forecast(days)` · `get_ad_performance(period, level=campaign|creative)` · `get_personal_events(date)`.

## 6. Безопасность и доступы

- Договор и соглашение о конфиденциальности — до получения доступов.
- Ключи API: только чтение в пробной версии; запись — по пакету и с письменного согласия. Ключи шифруются, клиент может отозвать их в своей системе.
- Разделение клиентов: `tenant_id` + row-level security в PostgreSQL, тесты на утечку между клиентами обязательны.
- Роли внутри клиента: владелец — всё; РОП — продажи и диалоги; таргетолог — реклама; менеджер — свои сделки; бухгалтер — загрузка файлов и финансы.
- Аудит: кто что смотрел и менял, действия ИИ.
- Резервные копии базы ежедневно, хранение 30 дней, проверка восстановления раз в месяц.
- После отказа от пробной версии — удаление данных клиента в течение 7 дней с подтверждением.

## 7. Этап 1 — Пробная версия (10 дней)

### 7.1. Цель

Показать клиенту за 10 дней его бизнес в цифрах и первые деньги от ИИ-продавца. Проверить на Яне всю цепочку: подключение → данные → показатели → Елена → ИИ-продавец → отчёт «было → стало».

### 7.2. Состав

1. Подключение источников (минимум): Excel/Google-таблицы по шаблону, CRM (amoCRM или Битрикс24) по ключу, Meta Ads, Kaspi Магазин, банк — файлом, 1С — файлами от бухгалтера.
2. Расчёт показателей раздела 4 (кроме прогноза денег из договоров — упрощённый прогноз по регулярным платежам).
3. Минимальный веб-экран показателей (одна страница + вход по ссылке/коду): выручка, чистая прибыль, себестоимость, заявки, заказы, конверсия, реклама и цена лида, деньги, предупреждения.
4. Отчёт «Ваш бизнес в цифрах» (PDF): где теряются деньги — по типам потерь (время ответа, ночные заявки, шаблонные ответы, неподтверждённая реклама, убыточные позиции, текучка).
5. Елена в Telegram (и/или WhatsApp): брифинг голосом в 08:00, ответы голосом и текстом на вопросы.
6. ИИ-продавец в WhatsApp и Instagram клиента.
7. Отчёт «было → стало» на 10-й день.

### 7.3. Функциональные требования

**Подключение (админка NORDIS, для нас):**
- создать клиента, указать пакет «пробный», даты 10 дней, налоговый режим и ставки;
- добавить подключение: тип, ключ/токен (поле скрытое), проверка соединения;
- загрузить файл (xlsx/csv/1С-выгрузка/выписка банка) с выбором шаблона;
- экран сопоставления статей клиента со справочником;
- экран сверки: чистая прибыль по месяцам — у клиента / у нас / расхождение.

**Загрузчики:**
- каждый загрузчик идемпотентен (повторная загрузка не дублирует данные), ключ уникальности — ID записи в источнике;
- расписание: CRM, Kaspi, Meta — каждые 60 минут; банк/1С — при загрузке файла;
- при ошибке — 3 повтора, затем статус «ошибка» в `connections` и уведомление нам.

**Шаблоны файлов (`templates/`):**
- ОПиУ по месяцам (статьи из 3.4);
- продажи по дням и филиалам;
- реклама по дням: кабинет, кампания, расход, лиды;
- ФОТ по должностям;
- для бухгалтера: список отчётов 1С — оборотно-сальдовая ведомость, взаиморасчёты с контрагентами, остатки товаров, валовая прибыль/себестоимость продаж, выписка банка в формате обмена 1С.

**Пилот Яны — первая загрузка:** её рабочая таблица (листы «ОПиУ», «Реклама_мес», «Реклама_день», «Продажи_день», «Сверка_таргета», «Юнитка_Passie», «Деньги»). Цель — чистая прибыль по месяцам 2026 совпадает с её ОПиУ до тенге. Файл хранится у Елены Дарс, в репозиторий не кладём.

**Елена:**
- брифинг в 08:00 по Алматы, 7 блоков: деньги, продажи, производство и склад, люди, сегодня, риски и сроки, личное; длительность 2–3 минуты; текст + голос;
- вопрос голосом или текстом → ответ за ≤ 10 секунд (текст) и ≤ 15 секунд (голос);
- «Личное» в пробной версии — только напоминания из `personal_events`, которые владелец сам надиктовал Елене. Заказ цветов и выставление счетов — не в пробной версии (см. Премиум/опции).

**ИИ-продавец:**
- база знаний клиента: товары, цены (только из прайса), доставка, оплата, акции, частые вопросы, возражения, книга продаж;
- режимы: `draft` (пишет черновик, менеджер одобряет в 1 клик) — дни 4–5; `auto` — с 6-го дня, если доля правок < 10%;
- передача человеку: жалоба, возврат, вопрос вне базы знаний, скидка выше порога, просьба клиента позвать человека;
- ведёт клиента до оплаты: даёт ссылку/счёт по правилам клиента;
- каждая сделка, где ИИ-продавец вёл диалог до оплаты, помечается `closed_by = ai_seller`;
- ответ ≤ 60 секунд, 24/7, параллельно 100+ диалогов.

**Отчёт «было → стало»:** время первого ответа, заявки без ответа, конверсия, ночные продажи, выручка за 10 дней к среднему за прошлые месяцы, расход на рекламу, расчёт эффекта по калькулятору (пессимистичный/реалистичный/оптимистичный).

### 7.4. Критерии приёмки

- [ ] Чистая прибыль Яны по месяцам 2026 совпадает с её ОПиУ (расхождение 0 ₸ или объяснено).
- [ ] Данные CRM, Meta и Kaspi обновляются автоматически не реже раза в час, 10 дней без ручного вмешательства.
- [ ] Елена правильно отвечает на 9 из 10 проверочных вопросов владельца (список вопросов согласуем с Яной до старта).
- [ ] Брифинг приходит в 08:00 ± 5 минут все 10 дней.
- [ ] ИИ-продавец: медианное время ответа ≤ 60 сек; ни одной неверной цены; доля передачи человеку ≤ 20%.
- [ ] Подключение нового клиента по чек-листу занимает ≤ 3 рабочих дня.

### 7.5. Не входит

Собственное мобильное приложение, запись в CRM, управление рекламой, прямое подключение 1С и банков, телефония.

## 8. Этап 2 — Лайт (900 000 ₸/мес; оборот 5–20 млн ₸)

### 8.1. Цель

Пробная версия без нашей ручной работы + приложение для собственника. Лайт = платформа + Елена + 1 ИИ-сотрудник (продавец).

### 8.2. Состав и требования

**Приложение NORDIS (веб + PWA на телефоне):**
- главный экран: показатели раздела 4 за сегодня/вчера/месяц, сравнение с прошлым периодом;
- предупреждения: кассовый разрыв, рост себестоимости, зависшие КП, расхождение рекламы;
- задачи и напоминания: от Елены, от ИИ-сотрудников, свои;
- кнопка Елены: голосовой вопрос прямо в приложении;
- роли пользователей (раздел 6), приглашение сотрудников.

**Деньги:**
- договоры: загрузка PDF → ИИ извлекает контрагента, суммы, сроки, график платежей → человек подтверждает → `payment_schedule`;
- прогноз денег на 14 дней по дням; предупреждение о разрыве за 7–14 дней с предложением (перенести закупку, ускорить оплату).

**Склад:** подключение МойСклад (JSON API) или еженедельная выгрузка остатков из 1С; запас в днях по SKU; предупреждение «товара хватит на N дней».

**ИИ-продавец:**
- запись в CRM клиента: создаёт сделки, меняет стадии, ставит задачи менеджерам (право записи — по согласию);
- ответы по-казахски (после теста качества);
- напоминание клиенту и менеджеру о КП через 3 дня.

**Биллинг:** учёт 1% с продаж ИИ-продавца по `billing_ai_sales`, ежемесячный акт для клиента с перечнем сделок.

**Онбординг:** чек-лист подключения в админке, статус каждого шага; цель — подключение за 1 рабочий день при стандартных системах.

### 8.3. Критерии приёмки

- [ ] 3 клиента месяц на Лайте без сбоев загрузки дольше 24 часов.
- [ ] Наше время на клиента ≤ 2 часов в неделю.
- [ ] Прогноз денег: ошибка остатка на 7-й день ≤ 10% на исторических данных пилота.
- [ ] Акт по 1% сходится с CRM клиента.

### 8.4. Не входит

ИИ-РОП, ИИ-таргетолог, управление рекламой, 1С по OData, банки по API, телефония.

## 9. Этап 3 — Бизнес (2 000 000 ₸/мес; оборот 20–100 млн ₸)

### 9.1. Цель

3 ИИ-сотрудника (продавец, РОП, таргетолог), прямые подключения к 1С и банкам, экран «Штаб» и сценарии «что будет, если». Подтвердить на клиенте цифры кейса из презентации.

### 9.2. Состав и требования

**ИИ-РОП:**
- проверяет 100% диалогов людей и ИИ-продавца по чек-листу книги продаж; оценка 0–100 и комментарий;
- ежедневно: рейтинг менеджеров, где клиент «замолчал» (последнее сообщение от нас без ответа > 24 ч), зависшие КП;
- отклонения: скидка выше нормы, возврат, отмена после оплаты, списание — в утренний брифинг;
- ставит задачи менеджерам в CRM (`auto`), предлагает изменения в книгу продаж (`propose`).

**ИИ-таргетолог:**
- ежедневно читает статистику Meta Ads по креативам; считает цену лида и цену клиента (связка лид → покупка через CRM);
- правила: остановить креатив, если цена лида > порога и расход > минимума (`auto` в рамках лимита); перенести бюджет в креативы с лучшей ценой клиента (`auto` в пределах ±X% дневного бюджета, иначе `propose`); увеличить общий бюджет — только `propose`;
- ежедневная сверка: списания с карты/счёта на рекламу против расхода по кабинетам; расхождение → предупреждение (как в кейсе: 3,78 млн ₸ без подтверждения);
- режимы: первые 2 недели только рекомендации, затем управление по согласию.

**Правила решений:** экран настройки трёх уровней для каждого ИИ-сотрудника с лимитами в тенге и процентах; изменения — только владелец.

**1С напрямую:** стандартный интерфейс OData платформы 1С (база опубликована на веб-сервере клиента или в облаке 1С). Чтение: остатки по счетам, взаиморасчёты, документы реализации, себестоимость, остатки товаров. Где OData невозможен — остаются файлы бухгалтера.

**Банки по API:** начинаем с банка, где счета у большинства клиентов; ежедневная выписка и остатки. Где API нет — файл или выписка через 1С.

**Экран «Штаб»:** все показатели, предупреждения, действия ИИ-сотрудников за день на одном экране; для руководителей — по ролям.

**Сценарии «что будет, если»:** владелец меняет цену, бюджет рекламы, численность, себестоимость → пересчёт чистой прибыли и денег (логика калькулятора эффекта NORDIS).

### 9.3. Критерии приёмки

- [ ] ИИ-РОП оценивает 100% диалогов за сутки; согласие с оценкой живого РОПа ≥ 80% на выборке 50 диалогов.
- [ ] ИИ-таргетолог: за 2 месяца у пилотного клиента стоимость клиента из рекламы снизилась, ни одного действия вне лимитов.
- [ ] Сверка рекламы с банком ловит 100% тестовых расхождений.
- [ ] У одного клиента чистая прибыль за 2 месяца выросла больше стоимости пакета (по калькулятору эффекта).

### 9.4. Не входит

Голосовой продавец на телефоне, сопровождение 24/7, ИИ-финансист и другие сотрудники сверх трёх.

## 10. Этап 4 — Премиум (3 300 000 ₸/мес; оборот от 100 млн ₸)

### 10.1. Цель

5 ИИ-сотрудников, режим нон-стоп: голосовой продавец на телефоне и сопровождение 24/7. Дополнительный ИИ-сотрудник — 200 000 ₸/мес.

### 10.2. ИИ-сотрудники сверх трёх (клиент выбирает двух; остальные — докупка)

| Сотрудник | Что делает | Данные | Действия |
|---|---|---|---|
| Финансист | Юнит-экономика по SKU и направлениям, ABC-анализ, убыточные позиции, рост себестоимости, предложения по затратам и налогам (только предложения, решение — бухгалтер/владелец) | ОПиУ, товары, заказы, 1С | `propose` |
| Маркетолог | Возврат клиентов из базы: сегменты, предложения в нужный момент, рассылки после согласования | заказы, клиенты, мессенджеры | `propose` → `auto` по шаблонам |

| Закупки и склад | Когда и сколько заказать, неликвид, дни без товара | склад, продажи, поставщики | `propose` |
| Рекрутер | Отбор рабочих кадров: вакансия, первичный отбор откликов | вакансии, отклики | `propose` |

### 10.3. Голосовой продавец на телефоне

- телефония с казахстанскими номерами (SIP-транк), входящие и исходящие;
- распознавание и синтез речи в реальном времени, задержка ответа ≤ 1,5 сек, русский и казахский;
- та же база знаний и правила, что у ИИ-продавца в мессенджерах; передача звонка человеку;
- запись разговоров с уведомлением собеседника; расшифровка → `dialogs`;
- запуск только после теста на записях реальных звонков клиента.

### 10.4. Сопровождение 24/7

- мониторинг загрузчиков и ИИ-сотрудников, автоматические оповещения дежурному;
- дежурный человек на связи; время реакции на сбой — в договоре (например, 30 минут);
- ежемесячная встреча с Еленой Дарс по итогам (если остаётся в пакете — раздел 12).

### 10.5. Опция «Личные поручения» (обсуждаем отдельно)

Сценарий из презентации (напомнить о дне рождения, заказать цветы, выставить счёт в Kaspi на оплату одной кнопкой) требует партнёрства с сервисом доставки и согласованного способа выставления счетов. В ТЗ закладываем как опцию после Премиума; в пробной версии и Лайте — только напоминания.

### 10.6. Критерии приёмки

- [ ] Голосовой продавец месяц работает у одного клиента; доля звонков, переданных человеку, не выше согласованной с клиентом; ни одной неверной цены.
- [ ] Сопровождение: все тестовые сбои замечены и обработаны в пределах времени реакции.
- [ ] Каждый из 6 дополнительных ИИ-сотрудников прошёл пилот у одного клиента.

## 12. Открытые вопросы

1. **Яна:** какая CRM, где идут заявки (WhatsApp, Instagram, Kaspi), какая 1С и где стоит база, в каких банках счета, есть ли складская программа.
2. **Юрист:** закон РК «О персональных данных» — хранение на сервере в РК, передача переписки покупателей во внешние ИИ-сервисы, согласия, запись звонков.
3. **WhatsApp:** через Meta напрямую или через официального партнёра; стоимость сообщений закладываем в пакеты.
4. **Речь:** какой сервис распознавания и синтеза даёт приемлемое качество на казахском (тест в спринте 2).
5. **Банки:** у каких банков клиентов есть API выписок для юрлиц; следим за открытым банкингом Нацбанка для бизнеса.
6. **Команда:** разработчик на частичную занятость для сервера, домена, WhatsApp; кто дежурит в Премиуме.
7. **Премиум:** остаётся ли личная встреча с Еленой Дарс раз в месяц.
